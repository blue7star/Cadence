### 1.3 关键事实

- **四级 WBS，不是阶段**：`一级项目 > 二级项目 > 工作事项 > 工作内容` 摊平成列；`工作内容` 才是那条任务。
  **没有**任务编号、阶段编号、父阶段编号、完成人、知情人，**也没有任何排期/阶段概念**。
- **日期两种写法混用**：`YYYY-MM-DD` 与 `YYYY/M/D`（不补零）。计划开始 57 ISO / **14 斜杠**；计划完成 63 / **8**；实际完成 12 / **5**。样本：`2026/12/1`、`2026/6/1`、`2026/8/18`。
- **13 条完全没有计划起止**（line 2/3/6/14/23/24/25/40/46/50/52/55/61），状态仍可能是「待开展」。
- **26 条已完成但没有实际完成时间**；另有 **3 条已完成但进度 0%**（line 34/47/49，这三条反而有实际完成时间）。
- **7 组同名同事项、不同日期**（周期性实例），例如「负责每周610AI专班会议布置及整理」；
  按 `工作内容 + 计划开始 + 计划完成` 统计，**0 组重复**——说明「标题+起止」在这份数据里天然唯一。
- 备注里 7 条是 `[自动生成 2026-09-11]` 这类**企管实例标记**，其中 4 条带尾随空格。
- `标签`/`批注` 全空；`优先级` 只有中/高；`进度` 只有 0%/100%。

## 4. 已定口径（2026-11-12 用户拍板）

1. **不造假阶段。** 工作事项是 WBS 分组，不是排期；导入后 `stages` 留空，不为了「有阶段」硬造一段。
   - 代价：这类任务没有阶段=没有叶子进度，状态只能整体改；日历上按整条区间呈现（实际表现待实现时验证）。
2. **分类默认不建。** 一级/二级项目只在预览里逐项勾选（映射到已有分类 / 显式新建）；不勾就留空。
   - 代价：84 条大概率全部无分类，直到人工勾选。
3. **去重键 = 工号 + 标题 + 计划开始 + 计划完成。** 企管没有任务编号，只能用业务键；本样本按此键 0 重复（7 组同名靠日期区分）。
   - 代价：日期被改过 = 新任务，旧任务留在库里，不自动删；想合并需另做「按标题找同源」，本批不做。

## 附：常规任务加「每年」频率（评估，未实现）

> 来源：企管 `工作频率` 有「每年」，而我们的规则只有日/周/月。**这是另一个独立决策**，不与导入绑定。

### 现状

- `rule.cycle` 只有 `day` / `week` / `month`，默认 `month`（`server.js:50-54`）。
- 生成：`cyclesBetween`（`server.js:231-253`）按日/周/月切周期；`stepPlanDate`（`:254-266`）算节点日期；`ensureInstances`（`:273-302`）落库。
- UI：三个页签「日常规/周常规/月常规」（`public/app.js:1191-1194`）；文案 `cycleCN`/`cycleLabel`（`:1130`、`:1181`）；月节点字段是「本月/次月 + 几日」（`:2434-2447`）。
- 导出：没有「频率」列，**不受影响**。

### 要动的位置

| 面 | 改动 |
|---|---|
| 周期切分 | `cyclesBetween` 加 `year` 分支：`key=YYYY`、`from=1/1`、`to=12/31`、`anchor=1/1`，guard 收紧到个位数 |
| 节点日期 | `stepPlanDate` 加年分支：`month(1-12)+day`，2/29 按当月天数夹取（与月规则一致） |
| 字段 | 建议新增 `monthNo`，**不要复用 `mo`**（`mo` 在月规则里是「本月/次月」，语义冲突） |
| 重排 | `regenRule` 现在按「本月及以后」删除（`server.js:329-330`），年度实例在 80 天窗口外，**一编辑就会被删且不重建**——必须把删除范围收到生成窗口，或对年规则把窗口延到次年 |
| UI | 加「年常规」页签 + 年度节点行（月份下拉 1-12 + 日 + 时间 + 策略）；`nodeDayText`/`cycleLabel` 补 `每年`；`isCrossMonth` 的跨月标记要覆盖「跨年」 |
| 校验 | `upsertRule` 目前**不校验 cycle**；未知值会掉进月分支（静默按每月跑）——加白名单，年规则才不会被误当月 |
| e2e | 新建年规则 → 实例 id `ri_<rule>_<YYYY>`、`plan_date` 正确、日历可见；连跑两次 `maintain` 幂等；改规则后实例仍在；日/周/月回归不变 |
| 文档/版本 | `specs/features/` 与 `DEVELOPMENT.md` 的频率说明；按 INV-4 bump Z |

### 旧规则如何不受影响

- `cycle` 是 TEXT、默认 `month`，**无需迁移**；新分支只在 `cycle === 'year'` 时生效。
- 前提是加白名单并保持「未知 cycle 不静默当每月」；否则老数据里万一有空值/脏值，行为会变。

### 风险提示

- 年度任务常见于年末/年初，**节假日表目前只有当年**，跨年顺延可能算错（应视为已知限制或在生成时提示）。
- 生成窗口只有「前 40 天、后 80 天」，年度实例会晚出现；这是设计选择，需在文案里说清。
