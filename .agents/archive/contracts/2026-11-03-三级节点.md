# 契约：阶段下可再拆一级子任务（三级节点，不涉及责任人）

> **什么时候写**：`AGENTS.md` 里的 G2/G3 改动，开工前复制本文件为
> `docs/contracts/YYYY-MM-DD-短名.md` 并填完第 1 段。G0/G1 不写。

## 1. 任务（开工前填完才动手）

- **触发**：用户原话——「任务下发/专项可以细分到三级，看看大家的使用情况，再定（责任人）」。
- **要改的模块**：`server.js` 数据层、`server.js` 同步、`public/app.js` 状态层、`public/app.js` 日历、`public/index.html`。

### 1.1 范围：只做两种任务

| 类型 | 做三级 | 为什么 |
|---|---|---|
| `assign` 下派任务 | 做 | 跨期、要拆阶段 |
| `special` 专项 | 做 | 跨期、要拆阶段 |
| `temp` 临时 | **不做** | 当天的事，拆了反而累赘 |
| `routine` 常规 | **不做** | 重复生成、勾选要快；`regenRule` 按 `name` 恢复完成状态，同名子项会串 |

判断标准一句话：**只有要跨越一段时间推进的任务，才值得拆三级。**
`temp` / `routine` 即使接口传了 `pid`，服务端也强制拉平为一级；前端不给入口。

### 1.2 结构：给节点加 `id` / `pid`，数组保持扁平

`task.stages` 元素新增两个字段：

| 字段 | 含义 | 缺省 |
|---|---|---|
| `id` | 节点自身 id | 老数据没有 → 读取时按索引生成运行时 id，**不写库** |
| `pid` | 父节点 id；`null` = 一级阶段 | `null` |

- **不新建表、不落成 task 行。** 子任务没有独立分类、优先级、状态机，日历跟着父任务走、进度汇总到父任务。独立成行会引出父子去重、逾期传导、拖动校验一整套新规则。
- **硬上限三级**：`pid` 只能指向 `pid` 为空的节点。写入时校验，第四级一律拉平成一级（不报错，静默纠正——脏数据不该让人卡在保存上）。
- **父阶段的 `start`/`end` 不独立存在**：有子任务时，父阶段日期 = 子任务日期的并集（`min(start)` ~ `max(end)`）。父阶段被拖动时，子任务一起平移相同天数；子任务被拖动时，父阶段重算。

### 1.3 算法：三处必须一起改，漏一处就会显性出错

1. **进度按叶子算**：分母只数「没有子节点的节点」。
   `taskProg()` 与「全勾即完成」判定都改成看叶子。父阶段不计入——否则同一个子任务被算两次，进度提前到 100 或永远卡在 2/3。
2. **日历只出叶子**：`occOn()` 跳过有子节点的阶段。父阶段日期是子任务并集，跳过它不会丢内容，也不会同一天父子并存。
3. **相邻关系按同层算**：`dragCheck()` 里的「上一段/下一段」改为**同层兄弟**——子任务只和同一父下的兄弟比顺序，顶层阶段只和顶层比。按数组下标比会把「上一阶段的最后一个子任务」当成相邻段，误报重叠。

### 1.4 拖动规则

| 拖什么 | 行为 |
|---|---|
| 一级阶段（无子任务） | 整段平移，保持段长（现状不变） |
| 一级阶段（有子任务） | 整段平移，**所有子任务跟着平移相同天数**；不能压到前后顶层阶段 |
| 子任务 | 只改这一段，保持段长；父阶段重算为并集；校验父阶段新边界不压到前后顶层阶段 |
| 已完成节点 | 不能拖（现状，按节点 `done` 判定） |

### 1.5 界面

| 位置 | 改什么 |
|---|---|
| 新建／编辑弹窗（`assign` / `special`） | 阶段行右侧加「+子」；子行缩进、无「+子」（三级封顶）；子行日期默认继承父行 |
| 任务详情页左栏 | 阶段树：一级序号 `1 2 3`，子任务缩进、用 `·` 或勾选态标记；每个一级阶段可「+子任务」内联添加；子任务可单独删 |
| 勾选 | 父阶段勾选 = 它的子任务全勾；父阶段有子任务时不单独给勾选框（点了就是全勾/全不勾，容易误解，干脆不给） |
| 其他页面 | 今日待办、下派任务列表、承接台、管理者看板全部沿用 `stages` 渲染，无需分叉；标题仍是父任务名，子任务名只出现在详情页和日历条目 |

### 1.6 不变量

1. 老数据（`stages` 无 `id`/`pid`）的进度、日历、详情页显示与现在**完全一致**，不做数据迁移。
2. 任何路径都造不出第四级节点：界面无入口，服务端静默拉平。
3. 有子任务的阶段，日历同一天只出一条（子任务），不父子并存。
4. 进度分母 = 叶子数；父阶段不重复计数。
5. 拖动不能把两条同层节点排成重叠；跨层互不干扰。
6. `temp` / `routine` 的行为一行都不变。

### 1.7 明确不做

- 节点责任人、节点级承接、节点级权限（另一份契约 `2026-11-03-阶段责任人.md`，**暂缓**，等这版跑一段时间再定）
- 第四级及更深
- 节点级交付物、附件、评论
- 子任务独立的分类 / 优先级 / 状态
- `routine` 规则的子节点

### 1.8 验收

`node _dev/verify.mjs --full` 全绿，e2e 新增断言：

1. 专项新建时加「阶段 + 子任务」，落库后详情页显示层级（父序号 + 子缩进）；
2. 三级封顶：子任务行没有「+子」按钮；
3. 勾完所有子任务 → 进度 100%（父阶段不重复计）；
4. 日历上该阶段区间内只出子任务条目，不出父阶段；
5. 拖子任务 → 父阶段起止跟着变，且压到下一阶段时被拦；
6. 拖有子任务的一级阶段 → 子任务整体跟着平移；
7. 老数据（无 `pid`）的专项/下派详情与改动前一致（回归）；
8. `temp` / `routine` 新建时没有「+子」按钮。
