# Cadence · 初级管理者工作台（MVP）

一期试点版。工号 + 姓名登录，数据存在这台机器的数据库里，多人共用同一份，改了立刻同步。

---

## 一、怎么跑起来

1. 这台机器要有 **Node.js 22 或更高版本**（双击后如果弹提示说找不到，去 https://nodejs.org/ 装一个，默认选项即可）。
2. 双击 **`启动工作台.bat`**，会弹出一个黑色窗口，里面会显示两个地址（浏览器也会自己打开一个）：
   - `本机访问：http://localhost:8788` —— 自己用
   - `同事访问：http://192.168.x.x:8788` —— 发给同事，同一个局域网就能打开
3. **这个窗口不要关**，关了服务就停了（数据不会丢，下次双击又回来了）。最小化没问题。
4. 想彻底停掉服务：关掉那个黑窗口，或者双击 **`停止工作台.bat`**。

## 三、这一版做了什么

| 评审要求 | 落地情况 |
|---|---|
| 发布任务（起止、达成标准、可选阶段） | 已做。执行人是组员，**不进管理者日历**，只在「发布任务」看进展 |
| 常规工作（日/周/月固定节点） | 已做。一个周期可挂多个节点，可跨月（本月 28 日 → 次月 15 日），节假日自动提前/顺延/跳过；日常规只按工作日生成 |
| 专项工作（可拆阶段） | 已做。阶段各自有起止时间，勾掉阶段自动算进度；**只能建给自己**，不能在这页派给别人 |
| 临时任务 | 已做。今日待办顶部一句话创建，可指定哪天、几点（默认今天），默认归「其他 / 临时事项」；同样只能建给自己 |
| 日历待办（双方即时更新、可拖拽改期） | 已做。每 7 秒拉一次最新数据；**格子里显示当天那一段活（阶段/节点），不是大项目名**；拖动卡片即改期，规则与已发生的记录不动 |
| 承接上级任务 | 已做。上级发下来的任务先进「任务承接台」，点「接收」就变成你自己的专项工作，接着就能拆阶段、派人 |
| 一条活分给几个人干 | 已做。三级子任务可以点名责任人：谁负责哪一段写清楚，他那边看得到自己那一段，点「加入待办」就进他自己的待办 |
| 下属常规工作可见 | 已做。默认只看汇总，点成员展开，「关注」某条才看它的完整节点；只读，不能改下属数据 |
| 下属专项工作可见 | 已做。在「发布任务」页，默认收起，点标题展开；按下属列出各自的专项和当前卡在哪一段，同样只读 |
| 专项知情人 | 已做。建专项时可以点名几个人知情，他们能在「我关注的任务」里看进度，改不了任何东西 |

登录使用工号 + 姓名免密码；汇报关系首次登录时自选，一个直属上级，有防环校验（不能选自己、不能选自己的下级）。**上级不是必填**：不设上级照样能发布、能承接，只是不会出现在别人的「下属」名单里。

**把整件事交给别人，只有「发布任务」这一条路。** 专项工作、临时任务、常规工作建的都是自己的事，承接人固定是你自己，页面上没有选人的地方——看到这里没有下拉，不是功能没做，是刻意锁掉的。要整件事交给别人，去「发布任务」；发出去之后对方在「承接台」接收，你还能跟踪进展。

**只把其中一段分给别人，不用另开一条任务。** 任何一条任务里（自己建的专项、别人交给你的活都算），在阶段计划里点「+ 子任务」，选上「谁做」就行。分出去的只是这一段，任务本身还归承接人管——所以这条不需要「发布」，也不会多出一条任务。

**发布可以点名给任何人，不限于直接下属。** 承接人下拉里是全公司同事，分「我的下属」和「其他同事」两组；派给不是自己下属的人，那条任务上会标一个「跨级」，过后一看就知道这条活是怎么过去的。反过来有一条硬规矩：**从没打开过工作台的人不能派**——派了他也收不到，活会躺在列表里假装有进展，所以当场拦住并说明原因。知情人不受这条限制，知情只是知会一声，不依赖对方账号。

**「发布任务」页一共四块，从上到下：** 我发布的任务 → 下属常规工作推进情况 → 下属专项工作推进情况（默认收起）→ 我关注的任务。最后一块汇总三样：你点过「关注」的下属常规、你点过「关注」的下属专项、以及别人把你设成知情的专项（会写明是谁让你知情的，越级跟项目就靠这一条）。自己发出去的任务不在这里，它在上面的「我发布的任务」里，同一件事不会出现在两个地方。

**一条活可以分给几个人干，这是这一版最要紧的变化。** 发给一个人的大活，可以在它的三级子任务上点名别的同事：谁负责哪一段写清楚。分两个人的边界有两条：

- **接收和派发是两件事。** 对方先「接收」，这条活才算归他管、进他的专项工作；他理完自己的计划再点「派发」，负责子任务的人那边才看得到。**没派发之前，被点名的人什么都看不到**——还在改的计划不会先跑到别人手上。
- **活交出去之后，你只剩两件事：看进度、改总截止。** 接收之后这条任务归他管，你改不了内容（发错了请在还没人接收的时候改回来）；但他排的计划不能超过你定的截止日，要延后得回来找你改。

他那边理完、派发之后，负责子任务的人会收到提醒，在承接台的「分给你的子任务」里点「加入待办」，那一段就以临时任务进他自己的待办。之后这一段改期、换人、被取消，他这边都会出现一条「有变动的任务」，点「知道了」就不再打扰。

周末或法定假日打开时，下属看板会自动改看**下一个工作日**的安排，并标注日期，不会出现整页「今日无节点」。

想在一条任务上细看（谁办、拆了几段、卡在哪段、还剩几天），点列表里的「查看」会进到一整页的详情：抬头是进度、阶段数、时间和承接人，左边是阶段时间线，右边才是可以改的字段。**组员的活你能看不能改**，那一栏会写成只读的清单，不会有改不动的灰框框在旁边碍眼。阶段写错了不用删了重建：每一行右边有「改」，名称和起止日期一起调；有子任务的阶段只让改名，时间跟着子任务走。

**日历上看到的是「这一段在干什么」。** 一条专项拆了阶段，格子里写的就是当天那一段（比如「看板搭建与试运行」），不再是「部门数据看板建设」这个大名字；名字下面还有一行更浅的小字，写着它属于哪件事，扫一眼就知道这段活挂在哪个大项目下。名字最多显示两行，不用悬停也能读完整。右边当天的清单也按段列，后面跟一个灰标签标着归属。**一天里活多不会漏**：格子放不下时下面会写「还有 N 条，点开这天看」，点一下右边就是当天的完整清单——常规工作没有优先级，以前排在最后，活一多就被挤没了，现在一条都不会消失。**专项阶段是连续日期区间，但只画在工作日**：周末和法定节假日不铺阶段条——阶段跨到周末只说明这个计划是连着的，不等于周末要干活；真必须落在某一天的单日节点，那天照常显示。常规工作同样只落在工作日。

**月历固定从「上月 26 日」开始，到当月最后一天结束。** 不随当月 1 日是星期几而变；26 日之前空着，星期列保持对齐。抬头会写明本视图从哪天起。

**点日历上的卡片，是「去右边改它」，不是「翻开它」。** 右侧会切到那一天，把这一条滚到眼前、亮一下，状态就在旁边选——从日历上点一条活，十有八九是想改状态或看看今天还剩什么，不该先被推到一整页详情里。真想细看，点那一行右边的「详情」。日历右上角常驻一句提示：拖动 = 改期，单击 = 在右侧清单里定位。

**不用点开也知道每条到哪一步了。** 卡片的浅色底和字色仍然只看来源：发布蓝、常规青、专项紫、临时橙；状态单独用左侧色条和右侧短文字表达：

- 灰条 = 待开展，默认状态不再额外占标题宽度
- 蓝条 +「进行中」= 正在推进
- 橙条 +「暂缓」= 暂时挂起
- 绿条 +「已完成」+ 标题划掉 = 已做完
- **红框 +「逾期」= 已逾期**：该结束的日期已经过了、活还没干完。红框不会盖住来源底色，左侧色条仍保留当前状态；已完成的不算逾期

被规则调整过日期的常规工作，右下角会有一个棕色小三角。

**拖动卡片 = 改期，不是把活交给别人。** 没拆阶段的活整段一起挪，工期天数不变；专项、发布任务拖的是当前这一段，段长不变，也不能压到前后段上；常规工作只改这一次，规则不动。下面这些拖不动，鼠标停在格子上就会写原因：没做完的任务拖到过去、已经完成的任务或阶段、常规工作或专项阶段拖到周末和节假日、阶段压到相邻阶段。上级派给你的任务改期后，对方能看到新日期。

**想设成「暂缓」不用点详情。** 列表每行右边有个状态下拉（待开展 / 进行中 / 暂缓 / 已完成），选中就存下去；常规工作的安排行同样能改——今天实在做不完，挂「暂缓」比先点进去翻表单实在。日历右侧的专项阶段行也是同一个下拉，改的都是整条任务的状态。

## 四、数据在哪，怎么备份

- 数据库文件：`data\workbench.db`（SQLite，单文件）
- 备份：**停掉服务后**，把这个文件复制一份即可；恢复就是换回去。
- 换机器：整个文件夹拷过去，装好 Node，双击启动就行。
- 操作日志：同一数据库里的 `op_log` 表，记录了谁在什么时候登录、提交了多少条改动——试点期看使用情况用。

## 五、这一版明确不做（按评审结论）

- 不发邮件、不接企业微信、不做手机推送 —— 只有站内提示
- 不做验收/评分，不能当绩效依据
- 不做管理员纠偏、不做组织架构同步（花名册写在数据库里，人工维护）
- 不单独适配手机
- 没有密码找回、没有权限分级 —— **仅限试点范围使用**，别放敏感信息

## 六、常见问题

**同事打不开 `http://172.17.x.x:8788`？**
先确认在同一个局域网；再确认服务那台机器的防火墙放行了 8788 端口。

**两个人同时改同一条任务？**
后保存的覆盖先保存的。这一版没做冲突提示，建议一个人负责一块。

**任务分类怎么维护？**
不用集中维护。新建或编辑任务时，在「任务分类」两个框里直接写一级 / 二级；写过的会自动出现在输入提示里，写错也不影响任务本身。「设置」里那一块只是看用过哪些分类，没有增删入口。

**填了一半点到旁边，内容会丢吗？**
不会。新建 / 编辑的窗口里已经填了东西时，点窗口外面的灰底或者按 Esc 都不会关，窗口会轻抖一下并提示「内容还没保存」——要留下就点「保存」，确实不要了点「取消」。一个字都没填的时候，点外面还是直接关掉，不添麻烦。

**「停用」和「删除」差在哪？**
停用只是**今后不再生成**：今天和更早在日历里的安排原样留着，明天以后的自动撤掉，点「启用」就恢复。删除是**彻底删掉**：这条常规连同它排过的全部安排一起消失，删了不能恢复。所以想暂时不做了用停用，想彻底不做了才用删除。

**花名册要改（新人入职、换上级、有人离职）？**
不用自己动数据库。按下面这张表填好交给开发同学，他执行一次就生效——导入后大家刷新页面即可，不用重启，也不影响已经建好的任务：

| 工号 | 姓名 | 岗位 | 部门 | 上级工号 |
|---|---|---|---|---|
| 1012 | 王磊 | 产品组组长 | 产品部 | 1001 |
| 1002 | 李明 | 产品经理 | 产品部 | 1012 |

- **上级工号**决定「谁能看到谁」：填了上级，这个人的常规工作就会出现在上级的下属看板里；**留空的话，他第一次登录时自己选一个上级**，选完就存下来了。
- **两种方式结果一样**：「表里填」和「本人自己选」记的是同一个地方，谁的上级是谁只有一个答案，不会出现两套说法。
- **留空不会把自选的冲掉**：以后你再导一次花名册，上级那一列还空着，也不会动他已经选好的上级——只有你明确填了工号，才按表上的改。
- **填错了想撤掉**：那一列写一个 `-`，就清空这个人的上级，让他重新选。
- **换上级**就是改这一列再导入一次，同一个人重复导入是更新，不会出现两条。
- **有人离职**：告诉开发停用他的工号。停用后他登录不了、也不再出现在任何人的下属里，但他之前做过的事和日历里的记录都还在。
- 导入前会先检查一遍（工号重复、姓名空着、上级工号写错都会指出来），有问题一条都不会写进去，改好再导一次就行。

**提示"保存失败"？**
黑色窗口关了，或者网络断了。重新双击启动，页面会自动重连，刷新一下即可。

**双击后窗口全黑 / 一闪就没了？**
这是上一版启动脚本的编码问题（已修）。现在还遇到，按顺序排查：先双击 `停止工作台.bat` 关掉可能残留的进程，再双击 `启动工作台.bat`；如果窗口里提示"端口 8788 已被占用"，说明服务其实已经在跑，直接在浏览器打开 `http://localhost:8788` 就行。

**窗口里显示"没有找到 Node.js"？**
按窗口里给出的三步装一下 Node.js（默认选项即可），装完重新双击。

**怎么知道工作台更新了？**
新版本上线后，打开工作台会自动弹出这次的更新内容，看完点「知道了」，之后就不会再打扰你。页面右上角一直有一个版本号小标（如 `v0.2.0`），想回忆哪一版改了什么，点它就能翻到历次更新记录。版本号在别人那台电脑上是各自提示的，不影响你自己的使用。

数据库文件不进仓库（`data/` 已忽略），因此从仓库拿到的是一份干净代码，第一次启动会自动建库并写入内置花名册；示例数据在「设置 → 数据 → 载入示例数据」里点一下。
