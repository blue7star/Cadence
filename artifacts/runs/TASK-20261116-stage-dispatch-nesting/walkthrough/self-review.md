## 逐条自审

1. **派出去那一段的状态**：改前是「已派发 · 待加入」（橙色状态在右、下拉在左），改后是「待接收」；同一位置只保留一个「改派」下拉和「撤回」按钮，没有同时出现两个「谁做」，没有把责任显示两遍。
2. **责任转移可读**：改后那一行不再有勾选框（改动前的勾选框也没有出现在待接收段上），完成权归子专项；下拉里显示的仍是待接收的承接人（陈静），与「待接收」不矛盾。
3. **提示文案**：派发提示从「派发之前，对方那边什么都看不到」改成「派发之后会变成一条子专项，等对方接收才生效」；同一屏里不再出现「加入待办」的旧说法。
4. **第三级**：`02` 里派发按钮呈禁用态，按钮右侧与子任务行各有一句「第三级不能再派」/「子专项最多三层，这一级不能再派」；`+ 子任务`、`改`、`删` 仍在，符合「只是不能再往下派」。点按钮无反应（e2e 断言 `disabled`）。
5. **未派发的段不受影响**：两图里「详情页改版」都保留「未派发」+「王浩」下拉，说明新链路只接管已派发的段。
6. **对齐与溢出**：1600 宽下阶段树三行没有换行、没有横向滚动条；「撤回」按钮与下拉在同一行内右对齐，右侧「任务信息」卡片宽度未变；左导航、页头、KPI 四格与改前一致。
7. **回归观感**：改前/改后同一任务的 KPI 都是 0% / 0 / 2，说明「派出去但没接收」不会偷偷改分母或进度；版本号从 v0.10.0 变为 v0.11.0，其余页头元素未动。

## 已知不足（留给下一轮，不假装做了）

- 「改派」下拉只有 `title` 提示，没有常驻文字标签；行内空间够，但用户要悬停才知道这是改派。等有第二处需要区分「改谁做」和「改派」时再加标签。
- 已接收的子专项在父方只显示「由 X 负责」，没有「撤回/换人」入口——这是本轮明确的范围外，接口也会拒。
