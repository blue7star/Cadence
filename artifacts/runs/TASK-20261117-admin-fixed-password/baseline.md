# Baseline — admin 初始口令每次重启都变

- base_revision: `06e7005`（v0.12.1）
- 采集时间: 2026-11-17
- 只读采集；真实库未改写。

## 现状

- `server.js` 的 `ADMIN_FIRST_PWD` 自执行分支：
  - 行不存在或 `must_change=1` → `crypto.randomBytes(9).toString('base64url')` 生成 12 位随机口令，`setAdminPassword(pwd, true)` 写库，并把明文打印到启动日志。
  - `must_change=0` → 返回空串，不打印、不写库（这一条是对的，需保留）。
- 启动日志文案：「这是本次启动新生成的初始密码……改密之前每次重启都会换一个新的（旧密码立即作废）」。
- `_dev/verify.mjs` 的断言固化了轮换行为：「未改密时重启：打印新密码，旧密码作废、新密码可登录且仍要求改密」，其中要求 `secondPwd !== firstPwd`。

## 观测（本次工作期间的重启）

- 本机服务在 2026-11-17 多次重启（v0.12.0/v0.12.1 交付与截图期间），每次启动日志里的 admin 初始口令都不同；累计观测到 5 次重启对应 5 个不同口令。
- 因为 `must_change=1` 未被清掉，重启必然进入生成分支，所以用户遇到的「每次重启都换一个密码」可稳定复现。
- 按项目「明文口令不进文档」的规矩，此处不复述这些随机口令。

## 复现路径（改前）

1. 保证 `admin_auth.must_change=1`（未完成首次改密）。
2. 启动服务，记录日志里的初始口令。
3. 停止后再次启动，比对日志：口令变得不同，上一次的口令立即失效。
