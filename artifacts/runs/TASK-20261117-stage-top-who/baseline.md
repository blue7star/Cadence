# Baseline — 一级阶段行没有「谁做」入口

- base_revision: `2438947`（v0.11.1）
- 采集时间: 2026-11-17
- 只读采集：`data/workbench.db` 未被修改；命令均为只读查询/代码定位。

## 1. 现状：入口只存在于二级行

- `public/app.js` 的 `stageTreeHTML()` 里，一级阶段行（`.stage`，非 `.sub`）只有编号、名称/日期、「改」「+ 子任务」「删」；「谁做」下拉（`data-act="stage-who"`）只在 `kids.map(...)` 的二级行渲染。
- `public/app.js` 的 `stage-sub` 动作要求先展开 `.subadd` 表单，填名称/日期/选人，再点「加」；加了以后还要按 `task-dispatch` 才会落子专项。
- `server.js` 的 `dispatchTask()` 只遍历 `s.pid` 非空、`who` 有值、`whoAt` 空的阶段；没有「从一级阶段一步生成二级并派发」的入参。
- 因此，只有一级阶段的专项（例如演示库里的 `1002_sp1`、`1004_sp1`）在详情页没有任何可用的派发入口。

## 2. 老数据现状（只读统计）

命令：

```sql
SELECT id,type,title,stages FROM task;
```

统计结果（真实库只读）：

```json
{
 "routine|noid": 100,
 "special|noid": 5,
 "assign|id": 6,
 "special|id": 14
}
```

- `special` 里有 5 个一级阶段没有 `id`（如 `1002_sp1` 的「标签口径对齐 / 历史数据回刷 / 灰度验证」）。
- 这些正是「只有一级阶段」的任务；新入口必须能在没有 `id` 的老数据上工作，否则演示数据里点不动。

## 3. 老 `whoAt` 数据（已知限制，不在本轮迁移）

- 0.11.0 之前的二级段可能已有 `whoAt`（旧「加入待办」通道）。
- 详情页的派发提示条只统计 `pid && who && !whoAt && !child`；`whoAt` 已置位的旧段不会出现在提示里，本轮不迁移、不改写这些行，只在交付说明中登记为已知限制。

## 4. 复现路径（改前）

1. 以 `1002` 登录，打开专项 `1002_sp1`。
2. 左栏「阶段计划」只有三条一级阶段行；没有「谁做」下拉。
3. 要指定责任人，只能点「+ 子任务」→ 填名称 → 选人 → 点「加」→ 再点顶部「派发」，共 4 步；入口不可见。
