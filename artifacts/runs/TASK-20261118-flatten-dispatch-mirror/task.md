## 目标与范围

- `dispatch{topStageId|topIndex, who}` 直接把 pending 子专项挂到一级阶段（`parent_stage_id=一级段 id`），不再生成同名二级节点。
- 一级阶段行渲染：pending →「李明 待接收」+ 改派/撤回；accepted →「李明 承接 · 进行中 50%」+ 展开下属计划；无子专项且未拆时仍是「谁做」下拉。
- 子专项的阶段计划（只读）挂在一级行下方展开；「+ 子任务」拆多人路径（二级段 + 子行 + 含 N 个子任务）保持。
- 迁移：把子专项从 `auto` 子段改挂一级段，删除 `auto` 子段；幂等；`node server.js --migrate` 输出前后统计。
- 规格同步：server-api / server-data / app-ui / tooling / version。

## 风险与权限

- 风险理由：改的是派发落点与老数据形状，影响「子专项→父任务」的读侧聚合与完成态上行；迁移直接改真实库的 `stages` JSON 与 `parent_stage_id`。
- Human 已决策事项：不生成同名子段；老数据迁移方向；完成态权威不变；删除 auto 段而不是隐藏。
- Worker 不得自行决定的事项：迁移时发明新阶段、改子专项 owner/status/日期、改导出列、动可见集。
- 允许的工作区与破坏性操作：仅 `Cadence/`；真实库执行前用 `VACUUM INTO` 备份到 `data/`；不得清空或重建库。
- 停止与上报条件：见元信息 `stop_conditions`
