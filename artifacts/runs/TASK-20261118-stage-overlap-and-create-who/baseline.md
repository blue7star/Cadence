# Baseline — 同层重叠放行 + 阶段选人入口

采集时间：2026-11-18，基线提交 `777d90f`（0.14.0+99.777d90f）。

## 1. 同层相交判定（前后端各一份）

- 服务端 `server.js` `checkStageIntervals` ①：同层两两配对，闭区间相交即返回
  「…时间重叠…同一层两段不能占同一天，把其中一段挪开再存」。
- 前端 `public/app.js` `validateStages` 第 5 条：同样的两两配对，返回 `overlap`；
  文案由 `overlapMsg()` 生成（含「压上了」「把其中一段挪开再存」）。
- 前端 `dragCheck`：拖阶段时与前后同层段比较，`prev`/`next` 命中即拒绝；
  提示挂在 `#dragHint` 上并加 `warn` 类（黄色）。
- 现状后果：用户第 1 段 2026-11-18→11-19、第 2 段 11-18→11-20，保存被拦。

## 2. 保留的真错误

- `validateStages` 第 1 条：起止倒置。
- `validateStages` 第 6 条 + 服务端 `checkStageIntervals` ②：子段超出父窗口。
- `checkStageIntervals` ③ / `restatTaskSpan`：任务周期 = 一级阶段包络。

## 3. 三处「能产生阶段」的入口现状（改前）

| 入口 | 位置 | 改前是否有「谁做」 | 改前后续 |
| --- | --- | --- | --- |
| 新建/发布任务弹窗 | `taskModalBody` → `stageRowHTML` | 仅子任务行有；一级行只有「+ 子任务」 | 无 |
| 详情页「+ 添加阶段」 | `taskDetailHTML` 表单 `#sName/#sStart/#sEnd` | 无 | 添加后一级行才出现「谁做」下拉 |
| 阶段行「+ 子任务」 | `subadd` 表单 | 有 | 选人后只写 `who`，还要再点页面上的「派发」 |

- 详情页一级行「谁做」（0.12.0，`stage-who-top`）已存在且选人即派，是弹窗/添加阶段要复用的同一套语义。
- 派发通道：`dispatchTask` 的 `{topStageId|topIndex, who}` 分支生成同名同起止二级节点 + pending 子专项；
  `{stageId, who}` 可用于刚建的二级节点。
