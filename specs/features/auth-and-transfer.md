## 0. 一句话

把「工号 + 姓名」的无密码登录换成「工号 + 初始密码（=工号）」，并让每个人能把自己名下（含承接）的任务导成一份人可读、机器可回灌的 CSV；导入分批做，先认证与导出，再导入。

## 1. 与现行口径冲突的地方（先看这一节，不要跳过）

下面每一条都是**代码事实**与拍板口径的正面冲突。不是提醒，是必须做决定的地方。

### C1（已由新格式消除）阶段原先把 `id` / `done` / `pid` 挤在一格里

- 事实：`stages` 是 JSON 数组，元素 `{id,name,start,end,done,pid,who,whoAt,joinedAt,doneBy,doneAt}`；`applyStageOwners()` 先按 `id` 匹配旧段，匹配不到再按**下标**兜底（[server.js L509-L531](file:///d:/ai_project/ai_work/Cadence/server.js#L509-L531)）。`pid` 为空的段会被删掉 `who/whoAt/joinedAt`。
- 原冲突：`名称@开始@结束@负责人工号;…` 没有 `id`/`done`/`pid`，回灌会把已完成阶段变未完成、让父任务从 `已完成` 掉回 `进行中`（[server.js L755-L756](file:///d:/ai_project/ai_work/Cadence/server.js#L755-L756)）、把子任务拉平并清掉责任人。
- **结论：改成「一行一阶段」后这条自动消失**——阶段编号、阶段完成、阶段完成日、父阶段编号各自成列，不再靠一格字符串表达，D1 不再需要拍板。留下的约束是：导入必须按「阶段编号」匹配旧段，不能按下标。

### C2 分类存的是 id，不是名称；而且分类按人隔离、无重名约束

- 事实：`task.cat1/cat2` 存 `cat.id`（示例数据形如 `1012_c1`，[server.js L1082](file:///d:/ai_project/ai_work/Cadence/server.js#L1082)）；`cat` 表按 `owner_no` 隔离，`name` 上没有唯一约束；`stateFor()` 只返回**我自己的**分类树（[server.js L442-L446](file:///d:/ai_project/ai_work/Cadence/server.js#L442-L446)）。
- 冲突：只导名称，回灌要靠「在我的分类树里按名称反查 id」。两个坑：
  1. 同级重名 → 无法确定 id；
  2. **接收来的任务，cat1/cat2 可能指向发布人的分类 id**，在我这棵树里根本查不到——现在界面上这类任务的分类就是显示空。
- 建议（需拍板 → D2）：主列仍然导**名称**（人要读），文件末尾补两列 **`分类一ID`/`分类二ID`**（人忽略，机器优先用）。名称解析不到时不猜、不建，按「跳过 + 原因」处理；有 ID 列时以 ID 为准（且校验该 id 属于我）。

### C3 「完成日期」在库里没有任务级字段

- 事实：只有阶段级的 `doneAt`，且格式是 `YYYY-MM-DD`（[server.js L527-L529](file:///d:/ai_project/ai_work/Cadence/server.js#L527-L529)）；`task` 表没有 `completed_at`。
- 口径：你已明确「接受只到日期、不为它改数据模型」。
- 落地定义：导出列 `完成日期` = 当 `status=done` 时取所有叶子阶段 `doneAt` 的最大值，否则空；**导入时该列只读、忽略**（完成时间只能由勾选动作产生）。
- 后果：无阶段的任务被标成 `done` 时，这一列永远是空。这是现状，不是缺陷。

### C4 常规任务实例回灌后会被系统删掉

- 事实：`pruneOrphans()` 每次 `/api/state` 都会删掉 `type='routine'` 且 `detached=0`、`routine_id` 不在 `rule` 表里的任务（[server.js L332-L338](file:///d:/ai_project/ai_work/Cadence/server.js#L332-L338)）。
- 冲突：导入新建的常规任务没有 `routine_id` → 下一次刷新就消失，用户看到的是「导入成功，但东西没了」。
- 建议（需拍板 → D3）：新建的常规任务一律写 `detached=1`（语义就是「不跟规则走的脱钩实例」）。更新已有实例不动 `routine_id`。

### C5 「承接」的范围和导入红线互相打架

- 事实：任务被接收前，`owner_no` 仍是发布人，`assignee_no` 是我，`intake_status='pending'`、`type='assign'`。
- 冲突：这种行按「承接」该导出，但导入红线要求文件里 `owner` 必须是我 → 它必然被拒。
- 建议：导出就排除 `type='assign'`（含 `intake_status='pending'`）。「承接」按**已接收**理解（接收即所有权转移，`owner_no` 已是我、`type` 已变 `special`）。这样导出集合与导入红线的定义域完全重合。

### C6 `temp` 派生副本不能导

- 事实：子任务责任人点「加入待办」会生成 `type='temp'` 的副本，`stage_ref` 指回父任务的某一段（[server.js L980](file:///d:/ai_project/ai_work/Cadence/server.js#L980)）。
- 冲突：这些副本在承接人眼里也是「自己负责的任务」，但它们是从父任务阶段派生的镜像，导出再导入会变成独立任务，和父任务的勾选状态互相打架。
- 结论：导出、导入都排除 `type='temp'`（或 `stage_ref` 非空）。

### C7 不上 TLS + 初始密码 = 工号，是明写记录的已知风险

- 事实：`server.listen(PORT,'0.0.0.0')`，无 TLS、无反代（[server.js L1478](file:///d:/ai_project/ai_work/Cadence/server.js#L1478)）。
- 风险 R1（**Human 已接受，写进文档，不含糊**）：
  1. 明文 HTTP，同一局域网内可嗅探 `sid` cookie；**拿到 cookie 等于拿到身份**，绕开密码；
  2. 初始密码 = 工号，属于弱口令；工号在内部通常是公开信息，等于「默认全员可登录」；
  3. 登录页写「初始密码为工号」等于公开这条规则（但不展示工号名单，仍需要知道对方工号）。
- 缓解（第一批内做，不额外扩范围）：
  - cookie 加 `HttpOnly` + `SameSite=Lax` + `Path=/`，**不加 `Secure`**（http 下加了就发不出去）；
  - 失败 5 次锁 5 分钟 + 超管可见「仍在用初始密码」名单；
  - 文档与启动日志明写「仅限可信内网，禁止暴露到公网/访客网络」。
- 不做：TLS、反代、Secure、密码复杂度策略、找回密码。

### C8 `005822` 在当前仓库的库里不存在

- 事实：`data/workbench.db` 只有 8 个演示员工（1012/1001/1002/1003/1004/1005/1101/1102），没有 `005822`。
- 冲突：`auth.admin_no` 默认 `005822`，在演示库/CI 里超管功能整条不可用，且是**静默**不可用。
- 建议：配置读 `meta.auth.admin_no`，可被环境变量 `CADENCE_ADMIN_NO` 覆盖（e2e 用）；启动时若该工号不存在或 `active=0`，日志明确告警，接口返回明确错误，不假装成功。

### C9 全部接口绑会话后，现有 e2e 会大面积红

- 事实：`_dev/e2e.mjs` 163 项检查里，大量请求直接带 `me:'1012'` 之类参数（[app.js L2586-L2588](file:///d:/ai_project/ai_work/Cadence/public/app.js#L2586-L2588) 的同类用法）；Node 自带 `fetch`（undici）**不会自动保存 cookie**。
- 冲突：`me ≡ session.no` 一上线，所有带 `me` 的请求都会 403；`node _dev/verify.mjs --full` 必红，而它是提交前必过的那道门。
- 结论：e2e 改造是第一批的**正式工作项**，不是「顺手修一下」。需要：登录助手（每身份一次）+ 手动 cookie 头透传 + 换身份时重新登录。零依赖约束下不引 cookie jar 库。

### C10 新目录 `specs/features/` 没有任何蓝图声明归属，提交会被 M1 拦

- 事实：M1 要求「每个受保护路径都要被某个声明模块的 `paths:` 覆盖」（[gate.py L441-L455](file:///d:/ai_project/ai_work/Cadence/.agents/gates/gate.py#L441-L455)），而现有蓝图只声明到 `specs/modules/`。
- 处理：本文件放在 `specs/features/` 下（按你的要求「Spec 放 specs/ 下」），同时在 `specs/modules/tooling.md` 的 `paths:` 补 `specs/features/`。**这是提交这份 Spec 的前置条件**，不补就是 pre-commit 直接拦。

### C11 导入不用 multipart

- 事实：零依赖，手写 multipart 解析是纯风险。
- 方案：前端用 `FileReader` 读出文本，`POST /api/import/preview` body 是 `{csv}` JSON。上传上限 2 MB（现在全库 792 条任务，实测远小于此）。超过直接拒绝，不做流式。

### C12 登录错误文案必须合并

- 事实：现在 `/api/login` 会分别提示「花名册里没有工号 X」和「姓名不是 X」（[server.js L1317-L1318](file:///d:/ai_project/ai_work/Cadence/server.js#L1317-L1318)）。
- 冲突：换成密码后若保留差异化文案，登录接口就是一个**工号枚举器**，锁 5 次也拦不住慢速枚举。
- 结论：统一为「工号或密码不正确」。锁定提示单独一条，且不透露该工号是否存在。

### C13 状态枚举比你列的三项多一个「暂缓」（**已定：四值**）

- 事实：状态是四值 `todo / doing / paused / done`（[app.js L49-L53](file:///d:/ai_project/ai_work/Cadence/public/app.js#L49-L53)），界面就叫「暂缓」。
- 冲突：你给的格式口径是「待办/进行中/已完成」三项。照办的话，暂缓任务要么导不出去、要么被硬塞进这三类——两种都是数据失真。
- **结论（已拍板）**：导出枚举按 **待办 / 进行中 / 暂缓 / 已完成** 四值输出，导入只认这四个词。**不许降级合并**（暂缓不并入进行中，也不排除）。

### C14 「阶段负责人」回来了，但「派发时间」回不来

- 事实：子任务责任人只有在 `stages[].whoAt` 有值时才算「已派发」（[server.js L363-L365](file:///d:/ai_project/ai_work/Cadence/server.js#L363-L365)）；`whoAt` 由派发动作产生，不是人填的。
- 影响：已有任务按阶段编号匹配更新时，`who` 不变就会沿用库里的 `whoAt`（[server.js L519-L520](file:///d:/ai_project/ai_work/Cadence/server.js#L519-L520)），所以**更新路径不受影响**；但新建任务时阶段负责人只是「指定」，不是「已派发」——这是正确语义，不是缺陷，写在这里免得验收时被当成 bug。

### C15 `doneBy`（谁勾的）不导出

- 事实：阶段完成人 `doneBy` 由勾选动作写入（[server.js L527-L529](file:///d:/ai_project/ai_work/Cadence/server.js#L527-L529)）。
- 口径：文件里只有「完成」和「完成日」，没有完成人。更新路径按阶段编号匹配、完成态不变时保留原 `doneBy`；新建路径由导入人成为 `doneBy`。
- 验收时断言 **done / doneAt** 等价，不断言 `doneBy`。

## 3. 认证

### 3.1 口径

- 初始密码 = 本人工号；登录页提示「初始密码为工号，登录后请及时修改」。
- 登录后自助改密，**不做**强制首登改密。
- 重置密码只有超管一人：`meta.auth.admin_no`，默认 `005822`，可被 `CADENCE_ADMIN_NO` 覆盖。**不做**上级重置链。
- 登录页**不展示**工号名单。
- 超管可看「仍在使用初始密码」名单（含姓名、首次登录时间、首次登录 IP）。

### 3.2 存储

新增两张表，不动 `task` / `emp` 的既有列：

- `cred(no TEXT PRIMARY KEY, hash TEXT, salt TEXT, initial INTEGER DEFAULT 1, changed_at TEXT)`
  - 与花名册分表：`import-emp.js` 是花名册的写入口，认证数据不该混进它 upsert 的行里。
- `sess(sid TEXT PRIMARY KEY, no TEXT, created_at TEXT, last_seen TEXT, ip TEXT, ua TEXT)`
  - 多会话并存；滑动空闲 8 小时、绝对 30 天；退出即删行。

密码：`scrypt`（Node 内置，`N=16384,r=8,p=1,keylen=64`，16 字节随机盐），比较用 `timingSafeEqual`。零依赖。

首次登录时间/IP == `op_log` 里该工号 `action='login'` 的最早一条（`op_log` 已有 `ip`/`created_at`，不再加列）。

### 3.3 接口

| 接口 | 鉴权 | 行为 |
|---|---|---|
| `POST /api/login` | 公开 | body `{no,password}`；成功下发 `sid` cookie 并返回 `me`；失败统一「工号或密码不正确」；同一 `no`+IP 连续 5 次失败锁 5 分钟 |
| `POST /api/logout` | 会话 | 删当前 `sess` 行 + 清 cookie |
| `POST /api/password` | 会话 | body `{old,new}`；校验旧密码；改后 `initial=0`，**吊销该人其它会话**（保留当前） |
| `POST /api/admin/reset-password` | 超管 | body `{no}`；把该人密码重置回工号、`initial=1`、吊销其全部会话 |
| `GET /api/admin/initial-passwords` | 超管 | 返回 `{no,name,firstLoginAt,firstLoginIp}[]`，只列 `initial=1` 且已登录过的 |
| 其余所有 `/api/*` | 会话 | 见 3.4 |

`/api/version`、`/api/changelog` 保持公开（登录页要显示版本）。

### 3.4 会话与身份（`me ≡ session.no`）

- 服务端从 cookie 取 `sid` → `sess.no`，**不再信任**请求里的 `me`。
- 请求里若仍带 `me` 且与会话不符 → `403 {ok:false,msg:'身份与会话不一致'}`（显式失败，便于抓旧客户端，不做静默兼容）。
- 无会话 / 会话过期 → `401 {ok:false,msg:'登录已过期'}`；前端收到 401 一律回登录页并清本地 `me`。
- 前端 `localStorage` 里的 `me` 只用于显示，**不作为任何判权依据**。

### 3.5 静态文件

`public/` 继续公开（登录页本身要能加载）。真正的门在 API：未登录时 `index.html` 能打开，但 `/api/state` 401 → 前端跳登录页。

## 4. 导出（第一批）

### 4.1 范围（定义域）

只导**我直接负责或已承接**的任务，且：

```
type IN ('routine','special')
AND owner_no = :me
AND (assignee_no IS NULL OR assignee_no = :me)
```

明确不含：`type='assign'`（我发布、别人还没接）、`type='temp'`（`stage_ref` 非空的派生副本）、我只作为知情人的任务、我负责某一段但任务不在我名下的任务。

### 4.2 文件格式

- 接口：`GET /api/export/tasks.csv`（会话鉴权，只导当前会话的人）。
- 响应：`text/csv; charset=utf-8` + `Content-Disposition: attachment; filename="cadence-tasks-<工号>-<YYYYMMDD>.csv"`。
- 编码：**UTF-8 BOM**，`\r\n` 换行。
- 文件结构（固定顺序）：

```
第 1 行  # cadence-tasks v1
第 2 行  # 导出人：005822 王磊
第 3 行  # 导出时间：2026-11-10T14:03:00+08:00
第 4 行  中文表头
第 5 行起 数据，一行一阶段
```

- 所有以 `#` 开头的行都是注释，导入端一律跳过（表头之后出现注释行也跳过）；**表头 = 第一个非空且不以 `#` 开头的行**。导出固定写 3 行注释，导入只要求「至少 1 行注释 + 表头」，不要求恰好 3 行。
- 导入**按列名匹配**，与列序无关；比较前去掉列名首尾空白。版本只认 `v1`，其它版本整文件拒绝，不猜。
- 文件末尾空行忽略；只有注释和表头、没有任何数据行 → 拒绝。

| 级别 | 列名 | 取值 | 导入行为 |
|---|---|---|---|
| 任务级 | 任务编号 | `task.id` | 空 → 按续行规则向下填充；填充不到 → 拒绝 |
| 任务级 | 标题 | 原文 | 覆盖 |
| 任务级 | 类型 | `常规` / `专项` | 映射 `routine` / `special`，其它值拒绝 |
| 任务级 | 状态 | `待办`/`进行中`/`暂缓`/`已完成` | 映射 `todo`/`doing`/`paused`/`done`（见 C13） |
| 任务级 | 所属人 | 工号（=我） | 必须是本人，否则整文件拒绝 |
| 任务级 | 承接人 | 工号或空 | 空或本人，否则整文件拒绝 |
| 任务级 | 分类一 | 分类名称（查不到则空） | 名称解析；D2 落地后优先用 ID 列 |
| 任务级 | 分类二 | 同上 | 同上 |
| 任务级 | 重要 | `1`/`2`/`3`/空 | 1 低、2 中、3 高；其它值拒绝 |
| 任务级 | 紧急 | 同上 | 同上 |
| 任务级 | 开始日 | `YYYY-MM-DD` | 覆盖；格式或日期非法则拒绝 |
| 任务级 | 计划结束 | `YYYY-MM-DD` | 覆盖；不得晚于总截止（沿用 `upsertTask` 的校验） |
| 任务级 | 总截止 | `YYYY-MM-DD`（`due_date`，空则回落 `end_date`） | 只有发布人是我时可改，否则忽略 |
| 任务级 | 完成日期 | `status=done` 时取叶子 `doneAt` 最大值，否则空 | **只读，忽略** |
| 任务级 | 更新时间 | `updated_at` | **只读，忽略**（导入后由服务端写） |
| 任务级 | 分类一ID | `cat1` 原值（可选列，D2） | 优先于名称 |
| 任务级 | 分类二ID | `cat2` 原值（可选列，D2） | 优先于名称 |
| 阶段级 | 阶段编号 | `stages[].id` | 按编号匹配旧段；匹配不到视为新段 |
| 阶段级 | 阶段名称 | 原文 | 覆盖 |
| 阶段级 | 阶段开始 | `YYYY-MM-DD` | 覆盖 |
| 阶段级 | 阶段结束 | `YYYY-MM-DD` | 覆盖 |
| 阶段级 | 阶段负责人 | 工号或空 | 空 = 跟随承接人；非空必须存在且已激活 |
| 阶段级 | 阶段完成 | `1` / `0` / 空（空=0） | 覆盖；父任务 `status` 仍由叶子重算 |
| 阶段级 | 阶段完成日 | `YYYY-MM-DD` 或空 | 仅在 `阶段完成=1` 时有意义 |
| 阶段级 | 父阶段编号 | 同任务内的阶段编号或空 | 最多两级，指向不存在的段 → 拒绝 |

未在表里的 `std`（达成标准）、`time`、`publisher_no`、`routine_id`、`plan_date`、`source_id`、`intake_status`、`detached`：
- 更新已有任务时这些字段**原样保留**（补丁式，D5）；
- 新建时 `std`/`time` 取空。要把「达成标准」也导出来就得再加一列，当前口径没提，我按不加处理。

### 4.3 续行规则（这是格式契约的核心，必须按字面实现）

- **R1** 每个任务至少占一行。有阶段的任务，**每个阶段正好一行**；无阶段的任务只占一行且阶段级列全空。
- **R1a** 无编号阶段（规则实例的步骤，`ensureInstances` 只写 `name/date/done`）照样每段一行：`阶段编号` 列留空，`阶段开始`/`阶段结束` 都取该步骤的 `date`（与前端 `s.start || s.date` 同口径）。导出**不得**按 `id` 过滤把它丢掉。
- **R2** 任务级列只在该任务的**首行**有值；同一任务的后续行，任务级列必须为空。首行之后出现任何非空的任务级列 → 结构错误。
- **R3** 归属靠「最近一个非空的任务编号」向下填充；填充作用域在下一个非空任务编号之前结束。
- **R4** 某行任务编号为空、但其它任务级列非空 → 结构错误（无法判断是新任务还是续行），拒绝并报行号。
- **R5** 同一个任务编号在文件里只能出现一次（一个连续块）；重复出现 → 结构错误。
- **R6** 阶段编号在同一任务内必须唯一；`父阶段编号` 必须指向同任务内已出现的阶段编号。阶段最多两级（与代码一致），出现三级 → 拒绝。
- **R7** 行的物理顺序就是 `stages` 数组顺序，导入按文件顺序写回，不重排。
- **R8** 空单元格表示「无值」，不是空字符串。`-`、`null`、`NULL`、`/`、`无`、`N/A` 一律按非法值拒绝——不做模糊猜测。
- **R9** 导入按「阶段编号」匹配旧段；**不得**用下标兜底（下标兜底会把换序后的完成态嫁接到别的段上）。

### 4.4 表头与单元格校验（全部 fail closed）

- 未知列名、必需列缺失、列名重复 → **整文件拒绝**，报列名。
- 日期必须是 `YYYY-MM-DD` 且真实存在（`2026-02-30` 拒绝）；不接受 `2026/2/3`、`20260203`。
- 枚举、数字范围不命中 → 整文件拒绝，报行号与列名。
- CSV 引号不闭合、字段数与表头不一致 → 整文件拒绝，报行号。
- 单元格转义遵循 RFC 4180：含 `,`、`"`、`\r`、`\n` 时整体加双引号，内部 `"` 写成 `""`；不做 `\n` → `\\n` 之类的自定义替换（否则人看到的就不是原文了）。

### 4.5 常规任务的 `detached`（D3 落地口径）

- 导入**新建**的常规任务一律写 `detached=1`。
- 语义写死一句话，避免以后被当成 bug 报：**导入后的常规任务不跟随规则变化**——它是一次性生成的脱钩实例，不挂 `routine_id`，不会被 `pruneOrphans()` 删掉，也不会随规则改周期/改标题而变。
- 更新已有实例时**不动** `routine_id` 与 `detached`（补丁式，D5）。
- 导出「完成日期」= `status=done` 时所有叶子阶段 `doneAt` 的最大值，否则空；**导入只读、忽略**，完成时间只能由勾选动作产生（C3）。

## 5. 导入（第二批）

### 5.1 两段式：预览 → 落库

- `POST /api/import/preview` `{csv}` → `{ok, created:N, updated:M, skipped:[{line,no,title,reason}], digest}`
  - 服务端**只算不写**；
  - 结构/格式错误（§4.4）不进 `skipped`，直接 `400 {errors:[{line,column,reason}]}`，**不给部分结果**；
  - `digest` = 上传原文的 sha256，用于提交时校验「你确认的就是这份」。
- `POST /api/import/apply` `{csv, digest}` → `{ok, created, updated, skipped}`
  - 重算 digest，不一致 → `409`，要求重新预览；
  - 再次做完整校验（不能假设「预览过了」）；
  - 落库**复用 `upsertTask()`**，不新开裸 SQL 写路径（否则阶段归属、`due_date` 校验、通知、镜像回收全部绕过）。

### 5.2 任务级判定（不是行级）

文件先按 §4.3 还原成「任务 → 阶段数组」，再逐任务判定：

| 情形 | 动作 |
|---|---|
| 编号由续行填充得到，且在全库不存在 | 新建（`owner_no=我`；新建的 `routine` 见 D3） |
| 编号存在且 `owner_no=我`，类型在允许集合内 | 更新 |
| 编号存在但 `owner_no≠我` | **整文件拒绝**（红线，见 5.3） |
| 类型不在 `常规/专项` | 整文件拒绝（枚举错误，§4.4） |
| 日期非法 / `计划结束 > 总截止` | 整文件拒绝，报行号与列名 |
| 分类名称解析不到或有歧义 | 该任务跳过（不自动建分类），预览里报原因 |
| 阶段引用的工号不存在或未激活 | 该任务跳过，原因写清哪个阶段 |

### 5.3 红线（不是「跳过」，是整文件拒绝）

- 文件里任意一个任务的 `所属人` / `承接人` 不是本人（且承接人非空）→ `400`，返回前 5 个违规行号，**一行都不写**。
- 任意一个任务的编号在库里属于别人 → `400`，同上。
- 理由：这是防注入。逐行跳过会让「别人伪造几行混进来」变成静默丢弃，看起来成功了，实际发生了越权尝试；整文件拒绝才会被人看见。

### 5.4 幂等

同一份文件连续 apply 两次：第二次 `created=0`、`updated=M`，任务总数不变，第二次导入后的再导出与第一次完全一致（`更新时间` 除外）。

## 6. 两批边界

| | 第一批 `TASK-20261110-auth-export` | 第二批 `TASK-20261110-task-import` |
|---|---|---|
| 认证 | 全部（登录/改密/退出/会话/401/锁定/超管/初始密码名单） | 无新增 |
| 导出 | CSV + 前端入口 | 无新增 |
| 导入 | **不做** | 预览 + 落库 + 红线 |
| e2e | 登录助手 + cookie 透传（必须） | 往返用例 |
| 共用 | 字段定义 + 行分组/还原（导出侧生成续行，导入侧向下填充）抽成同一模块 | 复用第一批的定义与解析器，不复制第二份 |

第一批单独交付、单独验收；第二批以第一批的字段定义与行分组/还原解析器为准，**不允许各写一套**（否则「往返一致」在代码层面就不成立）。

## 7. 往返一致：定义与验收用例

**定义**：对任务集合 T，`Export(T) → 手动不改一个字节 → Import → Export` 得到的 CSV，除「更新时间」与「完成日期」（C3 派生）外，逐行逐列相等；任务数、每条任务的阶段数、阶段数组每个字段（`id/name/start/end/who/done/doneAt/pid`）相等。

**样例（用来对齐实现，不是完整用例）**：

```
# cadence-tasks v1
# 导出人：1012 王磊
# 导出时间：2026-11-10T14:03:00+08:00
任务编号,标题,类型,状态,所属人,承接人,分类一,分类二,重要,紧急,开始日,计划结束,总截止,完成日期,更新时间,分类一ID,分类二ID,阶段编号,阶段名称,阶段开始,阶段结束,阶段负责人,阶段完成,阶段完成日,父阶段编号
1012_t9,季度复盘,专项,进行中,1012,,经营分析,季度,3,2,2026-11-01,2026-11-30,2026-12-05,,2026-11-10T09:00:00Z,1012_c1,1012_c11,s1,数据准备,2026-11-01,2026-11-10,,1,2026-11-09,
,,,,,,,,,,,,,,,,,s2,初稿,2026-11-11,2026-11-20,1004,0,,
```

断言：导入后任务数 1、`stages.length=2`；`s1.done=true / doneAt='2026-11-09'`；`s2.who='1004' / done=false`；`start/end/due_date/cat1/cat2/imp/urg` 与导入前逐字段相等；第二次导出的文本与这份（除 `更新时间`）字节级一致。

至少包含这些用例（写在 `_dev/e2e.mjs` 里，`--full` 跑）：

1. **常规任务 + 三段阶段**（其中一段有子任务、指定责任人）：再导出任务数不变、阶段数=3、`pid` 关系不变、逐列相等。
2. **专项任务无阶段**：文件里该任务只占一行，阶段级列全空；再导出仍是一行。
3. **续行规则**：任一任务的第 2..N 行，任务级列必须为空；把某任务第 2 行的 `标题` 手工填上 → 导入被拒绝并报该行号。
4. **已完成任务**（叶子 `doneAt` 有值）：再导出 `状态=已完成`、`阶段完成=1`、`阶段完成日`、`完成日期` 与首次导出相同。
5. **暂缓任务**：再导出 `状态=暂缓`（见 C13）。
6. **分类两级 + 重要/紧急 1/2/3/空**：再导出名称一致；有 ID 列时 ID 也一致。
7. **空值**：`分类`/`阶段负责人`/`阶段完成日` 为空的组合，再导出仍为空，不变成 `null`、`-`、`N/A`。
8. **转义**：标题含 `,` `"` 换行；阶段名含 `@` `;` `\`：再导出与首次字节级一致（新格式不再需要自定义转义，只需要 RFC 4180）。
9. **列名匹配**：把表头列序整体打乱（列名不变）→ 导入结果与未打乱时完全一致。
10. **结构错误**：删掉「任务编号」列 / 加一列「备注」/ 把第 2 行任务编号清空并保留阶段列 → 均整文件 `400`，报列名或行号，库内 `task` 行数与 `updated_at` 未变。
11. **红线**：文件里 `所属人=别人` → `400`；编号属于别人 → `400`；均一行不写。
12. **预览不落库**：preview 后行数与 `updated_at` 未变；digest 与再次 apply 时不一致 → `409`。
13. **幂等**：同一文件 apply 两次，第二次 `created=0`、`updated=M`，行数不变。
14. **跨人分类**：接收来的任务（`cat1` 指向发布人分类）再导出时，名称可为空但 ID 列必须保留（依赖 D2-A）。
15. **规模**：当前库 792 条任务全量导出再导入，任务数守恒。
