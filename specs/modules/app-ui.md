# MOD-app-ui · 前端状态层、阶段与分工 UI、日历

paths: public/

## 职责
拉取 → 本地 `S` → 快照 diff → `save()` 的状态层；阶段树渲染（新建弹窗 `stageRowHTML` / 详情页 `stageTreeHTML` / 就地编辑 `sedit` / 加子任务 `subadd` / 列表卡片 `stageRows`）；日历（`occOn` / `calChipHTML` / `chipLate` / `calCells`）。
## 公开行为
- 任何会改数据的交互最终都走 `save()` → `/api/sync`，或六个动作接口之一。
- 日历与清单同源（同一个 `occOn`）。
- 「今日待办」顶部快速录入条：日期显示为可读词（今天/明天/后天/日期），点一下开原生选择器；时间默认收成图标，按需原地展开；临时任务落在所选日（`start=end`），非今天在按钮左侧提示将建到哪天、不跳页；日期在本次页面生命周期内记住，刷新回到今天。
- 录入条两个出口分工：**回车 = 直接建**（字段走默认）；**「＋ 临时任务…」= 不建任务，打开完整新建弹窗**，把已敲的标题、所选日期与时间预填进去，补类型/分类/优先级/达成标准后再创建；输入为空也可打开空表单。
- 常规工作页分四个页签：日常规 / 周常规 / 月常规 / **年常规**；年常规的节点写「几月几日」（`monthNo` + `day`），规则卡与标签显示「每年 X 月 X 日」，实例日期带年份（`fmtY`），一次显示今年与明年。
- **派成子专项的那一段**：行内不再有「谁做」下拉与勾选框，改显示子专项摘要——待接收写「待接收」，接收后写「状态 · 进度%」。待接收时给「撤回」与「改派」下拉；已接收显示「由 X 负责」，这两步本轮不支持（见 `MOD-server-api` 的已知边界）。一级行整段派一人时，摘要直接落在这一行上（0.16.1），不再另起一行。
- **一级阶段行直接设责任人（0.12.0 / 0.16.1）**：一级阶段行（任务为 `assign/special`、`depth < 3`、这一段未完成且还没有任何子任务）渲染可见的「谁做」标签 + 下拉；选中人=调用 `POST /api/task/dispatch {id, topStageId|topIndex, who}`。0.16.1 起子专项直接挂这一级段：派完后一级行显示「X 待接收」+ 改派/撤回；接收后显示「X 承接 · 状态 进度%」，进度与完成来自子专项。阶段 JSON 不新增节点，页面只有一行；已完成或已有子任务的一级行不渲染下拉（责任按子任务行分配）。
- **三个能产生阶段的入口都支持「谁做」并选人即派（0.15.0）**：① 发布/新建任务弹窗的每个一级阶段行；② 详情页「+ 添加阶段」表单（`#sWho`）；③ 阶段行「+ 子任务」表单。① 与 ② 是整段派一人，选中的人 = 保存/添加后立即调用 dispatch，子专项直接挂该一级段、落成「待接收」，不生成同名替身段；③ 是先建一条二级子任务段再把子专项挂到它上面（一个阶段拆多人的唯一形态）。不选人则保持原样；一级阶段的 `who` 不落库。
- **上级一层透视（0.16.0）**：一级阶段行即使已有子任务，也显示只读聚合负责人（`李明 承接` / `李明 待接收`，多个用「、」）；可编辑的「谁做」入口仍只在无子任务时出现。子任务行给「展开下属计划」，展开后渲染 `child.stages`（名称/日期/已完成|进行中|待开展），块内**没有**改/删/加子任务/谁做/派发控件；不再渲染第二层 child。完成态仍由下属维护向上汇总。
- **导出时间范围（0.16.0）**：点「导出 CSV」先开弹窗：起止日期 + 「全部」复位 + `#expPreview` 行数预览（`/api/export/tasks.csv?preview=1`）。范围口径与后端一致；`from > to` 在前端先拦，后端仍返回 400。
- **阶段行窄屏折行（0.15.1）**：`.mrow .row2` 与 `.subadd .row` 拆成「日期组 `.r2a` / 操作组 `.r2b`」，`flex-wrap:wrap`；日期组 `flex:1 1 200px`，操作组 `margin-left:auto` 并允许自身换行。所有「谁做」下拉限宽 `132px`、超出省略号（展开的原生选项仍完整）；默认项统一为「承接人自己做」。详情页「再加一段」用 `.addstage-row` 同一规则。约束：1024/1280 下不得出现页面横向滚动条，任何控件不得越出弹窗/卡片；SSR 模板不得输出字面量 `false`。
- **撤回后入口自动恢复（0.12.1 / 0.16.1）**：一级行整段派一人后，点这一行的「撤回」会收掉 pending 子专项；一级段本身原样保留，行内重新出现「谁做」，可以立刻再派同一人或换人。手动「+ 子任务」建的段撤回后保留，`who` 还原到该子任务行。老数据里 0.12~0.16 生成的 `auto` 子段由启动迁移清理，界面不再生成这种段。
- **第三级任务**：`state` 给出的 `depth ≥ 3` 时，「派发」按钮置灰并写明「子专项最多三层」，子任务行也不给「谁做」下拉——不让人点下去才报错。
- 子专项详情顶部写明「来自「父任务」的「某一段」」，并说明完成会汇总到那一段；子专项支持知情人。

## 不变量
- **身份只有一份来源**：`S.me` 来自 `/api/state`（服务端按会话给），前端不再存 `localStorage` 身份；任何接口回 401 统一走 `onAuthLost()`（停轮询、清状态、回登录页），不在半截页面上继续点。
- 登录页只录工号 + 密码，提示「初始密码就是你的工号」，不展示工号名单。
- **高频动作在顶栏，不埋进设置页**：导出是顶栏按钮（每页可见，一次点击）；账号区（头像 + 姓名 + ▾）下有「账号与密码」与「退出登录」，前者一步跳到设置页的修改密码卡片并聚焦。设置页不再承载导出。
- **界面改动必须先截图自审**（视口与 `_dev/e2e.mjs` 的 `--window-size` 一致，当前 1600×1000，改前改后各一张），逐条列出看出的问题，留痕在 `artifacts/runs/<task_id>/walkthrough/`——见 `.agents/review-checklist.md` B11。
- **两份 UI 各写各的，改一处必须改另一处**（#47 弹窗有「谁做」、详情页漏了）。每行有可辨认身份：编号 `1 / 1.1` + 子行缩进竖线。
- **阶段时间是人设的，不从子任务反推**；子任务只排窗口内，装不下拦下并说清谁出界。
- **日期校验单入口** `validateStages()`；计数/日历/相邻只认叶子 `leavesOf()`。
- **进度按子专项加权**：`taskProg` 对派出去的叶子用子专项摘要里的 `progress`，其余叶子按 `done`；父任务进度 = 叶子折算后的平均，不是 0/100。
- `INV-4 一级阶段本身不存责任人`：一级行的「谁做」只是派发入口；子专项直接挂一级段，一级阶段不得出现 `who`/`done`（服务端 `applyStageOwners` / `applyChildOwnership` 继续清）。完成态读子专项摘要。反例：e2e 9.9b「一级阶段行选人后一级阶段仍无 `who`，责任在 pending 子专项上」。
- **回传前剥掉读侧字段**：`ownRows()` 必须删掉 `stages[].child`（服务端挂在阶段上的摘要），否则它会跟着整段提交被写回库。
- `INV-2 编号跟时间走`：新增/改期后同层按 `start` 稳定重排，一级阶段按升序、子任务紧跟其父；`data-idx` 是数组下标，重排后必须重读 DOM，不能缓存。反例：e2e 6.9「11-07→11-08 落在 11-06 与 11-09 之间，排到第 3 段」。
- ~~`INV-3 跨年提示必须带年份`~~（2026-11-18 删除）：它约束的是「同层重叠提示」的文案，而同层重叠已按用户口径放行、不再提示；日期展示仍沿用 `fmtY` 的跨年提示规则，但不再作为不变量。
- 日历格子里是「阶段/节点」不是父任务；非工作日不铺区间条目；月历上月 26 日起；已完成不算逾期。

## 依赖与边界
- 只走 `/api/*`，不 require 任何服务端文件。
- 禁止：绕过 `validateStages()` 直接改 stages；把子任务当成独立 task 行。
