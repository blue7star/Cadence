# MOD-app-ui · 前端状态层、阶段与分工 UI、日历

paths: public/

## 职责
拉取 → 本地 `S` → 快照 diff → `save()` 的状态层；阶段树渲染（新建弹窗 `stageRowHTML` / 详情页 `stageTreeHTML` / 就地编辑 `sedit` / 加子任务 `subadd` / 列表卡片 `stageRows`）；日历（`occOn` / `calChipHTML` / `chipLate` / `calCells`）。

## 公开行为
- 任何会改数据的交互最终都走 `save()` → `/api/sync`，或六个动作接口之一。
- 日历与清单同源（同一个 `occOn`）。
- 「今日待办」顶部快速录入条可选日期（默认今天）与时间点；临时任务落在所选日（`start=end`），非今天只提示不跳页。

## 不变量
- **身份只有一份来源**：`S.me` 来自 `/api/state`（服务端按会话给），前端不再存 `localStorage` 身份；任何接口回 401 统一走 `onAuthLost()`（停轮询、清状态、回登录页），不在半截页面上继续点。
- 登录页只录工号 + 密码，提示「初始密码就是你的工号」，不展示工号名单。
- **高频动作在顶栏，不埋进设置页**：导出是顶栏按钮（每页可见，一次点击）；账号区（头像 + 姓名 + ▾）下有「账号与密码」与「退出登录」，前者一步跳到设置页的修改密码卡片并聚焦。设置页不再承载导出。
- **界面改动必须先截图自审**（视口与 `_dev/e2e.mjs` 的 `--window-size` 一致，当前 1600×1000，改前改后各一张），逐条列出看出的问题，留痕在 `artifacts/runs/<task_id>/walkthrough/`——见 `.agents/review-checklist.md` B11。
- **两份 UI 各写各的，改一处必须改另一处**（#47 弹窗有「谁做」、详情页漏了）。每行有可辨认身份：编号 `1 / 1.1` + 子行缩进竖线。
- **阶段时间是人设的，不从子任务反推**；子任务只排窗口内，装不下拦下并说清谁出界。
- **日期校验单入口** `validateStages()`；计数/日历/相邻只认叶子 `leavesOf()`。
- `INV-2 编号跟时间走`：新增/改期后同层按 `start` 稳定重排，一级阶段按升序、子任务紧跟其父；`data-idx` 是数组下标，重排后必须重读 DOM，不能缓存。反例：e2e 6.9「11-07→11-08 落在 11-06 与 11-09 之间，排到第 3 段」。
- `INV-3 跨年提示必须带年份`：提示单用完整日期（`fmtY`），不动全站短格式 `fmt()`；同一提示要点名两段（含序号）并给出重叠区间。反例：e2e 6.9「压到中间段」断言文案含 `2026-11-09 到 2026-11-10`。
- 日历格子里是「阶段/节点」不是父任务；非工作日不铺区间条目；月历上月 26 日起；已完成不算逾期。

## 依赖与边界
- 只走 `/api/*`，不 require 任何服务端文件。
- 禁止：绕过 `validateStages()` 直接改 stages；把子任务当成独立 task 行。
